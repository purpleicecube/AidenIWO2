# 02 - SYSTEM OVERVIEW (Simple)

## Core Pattern
Manager-worker model:
- Tier 1 = manager (policy, approvals, routing)
- Tier 2 = worker (validation + execution)

## Non-Negotiables
1. Keep 2-tier boundary.
2. Keep PocketFlow as orchestration engine.
3. Keep GCC memory contract behavior.

## Request Lifecycle
1. Work order enters API.
2. Tier 1 policy gate checks mode and rules.
3. Tier 1 dispatches to Tier 2.
4. Tier 2 validates schema and executes.
5. If blocked, Tier 2 emits BDM marker back to Tier 1.
6. Tier 1 resolves or pauses for human decision.

## Hard Rule
No Tier 2 to Tier 2 direct chaining.

## GCC Memory (Plain English)
Use GCC memory as shared context between steps.
Use it for:
- routing context
- correlation IDs
- execution breadcrumbs

Do not use it for:
- secrets
- huge raw payload dumps
- hidden side effects
